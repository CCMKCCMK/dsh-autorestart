# 守夜人（sentry）—— 未来可能要做的功能

> 这是一份**本地存档**，不是要发布的功能说明。本目录下的源码**不参与构建、不会被加载、也不在 npm 包里**（`package.json` 的 `files` 只收 `docs/*.md`，不收子目录）。
> 保留它是因为：这个洞（重启窗口之外没有任何自动兜底）**今天仍然存在**；将来若决定补，这份东西能省下从头再查一遍的力气。

## 它想解决的问题

DSH 可能进入一种自身无法恢复的状态（2026-10-30 真实出现过一次）：

- 桌面客户端**0 个进程**；
- profile 被官方 `sanitizeProfile` 清空（`dsh.profile.bundles` 没了、`cordis.patch.yml` 变成 `[]`）；
- 本插件跟着 profile 一起被摘掉。

这时**没有任何东西会把它拉回来**：

- **看门狗**不管 —— 它只在本插件主动重启宿主的那一刻布防，宿主起来就撤防；
- **开机自启守护（supervisor）**也不管 —— 它由宿主启动，宿主死了它也死。

守夜人就是补这一格的：一个**装在 DSH 之外、由系统在登录时拉起**的常驻进程，插件和 profile 都没了它还在。

## 它当时是什么形态

- `lib/sentry.js` —— 纯判据（什么时候该救、什么时候该停），约 850 行；
- `lib/sentry-install.js` —— 装/卸（写登录任务、被拒时降级到启动文件夹），约 845 行；
- `supervisor/sentry.js` —— 守护进程本体，约 1480 行，**契约上独立**：会被拷到 profile 之外运行，只 import `node:` 内建，不 import 插件里的任何东西；
- `docs/sentry.md` —— 原始设计文档；
- 两份测试。

启动方式：Windows 登录任务 `schtasks /SC ONLOGON`（被拒时降级为启动文件夹里的 `.cmd`），与 DSH 完全无关。

## 关键事实：它的判据里没有「插件」

当时的判定只看两件事：**进程数是不是 0**、**超过宽限期多久**。它**不读插件加载状态**。

所以它管的是「**连进程都没有**」；「宿主活着、但某个插件被排除」是**另一条线**（本插件启动时读日志 → 只提示 → 人点一下才恢复那一个）。两者不要混。

另外：读不到进程表时它**不算 0**，宁可不救 —— 这条设计要保留。

## 为什么 2026-11-01 删了

用户拍板：「与『关就是关』冲突，不再维护」。既然用户关掉自动回滚之后就不该有任何东西在背后悄悄把宿主拉回来，一份常驻守护与这条正面冲突。删除提交 `0b56631`。

**删掉时它从未接线**：不注册任何工具、不会自动安装自己、没有 clean-exit 钩子，唯一痕迹是打包清单。也就是说，它是「造好了没接电」，不是「一直在值班」。

## 如果将来要接起来，这些必须逐条做完

1. **先解决「关就是关」的冲突**：要么给它一个独立、说得清的开关（例如「窗口之外的兜底」），要么明确改成用户显式安装才存在。不能默认静默运行。
2. **安装与卸载都要完整**：确认卡片、拷到 profile 之外、写登录任务；卸载时把任务和文件一起清掉，不留垃圾。
3. **状态文件放在 profile 之外**（`<stateDir>/sentry/`）：profile 被清空时它必须还活着。
4. **判据保持保守**：进程数读不到 ≠ 0；宽限期内不动作；每小时有次数上限；宿主正常退出时写 clean-exit 标记，有标记就不救。
5. **拉起宿主的那条命令**必须在桌面版真机上验证过（拉起 Electron 客户端，不是 `dsh web`）。
6. **与看门狗互斥**：两者都能拉起宿主，必须保证同一时刻只有一个动手。
7. **真机演练**（发版的硬要求）：真的杀掉进程、真的清空 profile，跑一次，核对它把人救回来了；不能只在隔离目录里跑 `--status` / `--once`。
8. **它自己挂掉怎么办**：登录任务被系统禁用、Node 路径变了，都要能被发现。
